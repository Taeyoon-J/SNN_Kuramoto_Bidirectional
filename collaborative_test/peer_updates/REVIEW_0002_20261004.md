# Peer review: patch_v2 a6740b8 (2026-10-04)

Read-only fetch; no merge into `patch_v2_sw`. New reports are
`PV2_0004_percomp_geo/README.md` and `PV2_0005_ceiling_prior/README.md`.

The most transferable insight is **per-component spike threshold
calibration**. A product over four nonnegative correlations is much smaller
than a single correlation. The peer initially evaluated it at a stale
threshold .40 and saw little benefit, but a validation-selected threshold
near .010 produced a three-seed test mean FG-ARI .5105 / foreground IoU
.4967 / object IoU .3689 on their own contract. Their render, split, and
Slot reference differ from ours, so these are *not* directly comparable to
our fixed HDF5 results.

Our prior SW_0010 sweep only lowered the product threshold to .10, which may
still be far too high. SW_0026 will test .0005-.10 (plus the old .50 control)
on our own SW_0003/SW_0004/SW_0011 checkpoints and fixed validation split,
using the existing actual-spike classifier. This is classifier calibration,
not a core architecture change.

Peer `PV2_0005` also re-measured an oracle-coupling diagnostic: perfect graph
training did not fix spike grouping, and a tighter spatial prior .35 helped
their own 100-image seed-0 validation while geodesic five-step worsened it.
The oracle experiment is not a deployable model score, and graph-prior
effects should not be transferred blindly. We defer graph changes until the
cheap threshold calibration above is measured locally.
