# SW_0006 — 동료의 spike 동기화 분류법 재검증

Status: fixed-split validation complete; no core retraining or production-code merge. Mixed result.

## 쉽게 설명하면

동료 `patch_v2`의 커밋 `5a29422`는 **같은 시점에 spike를 내는 patch를
서로 연결하고, 연결된 덩어리마다 물체 하나로 보는 방법**을 추가했습니다.
가장 큰 덩어리는 배경으로 정합니다. 이번 테스트에서는 그 아이디어를
우리 모델이 이미 만든 spike에 적용합니다. 모델 자체는 바꾸지 않습니다.

동료의 점수는 `clevr_with_masks` 240×320 이미지, 16×16 grid와 다른
학습·검증 분할에서 나왔습니다. 우리는 CLEVR HDF5 128×128, 검증 ID
1320–1639, 동일한 `evaluation.py` 기준으로 다시 계산합니다. 따라서
점수를 직접 복사하거나 동료 데이터와 섞지 않습니다. 정답 물체 개수는
분류에 사용하지 않습니다.

원본 방식처럼 실제 layer spike를 사용하고, 연결 임계값 다섯 개를 검증
데이터에서 비교했습니다. 우리의 4개 oscillator component를 따로 비교하는
변형도 함께 검사했습니다. 모두 검증 데이터에서만 비교했으며, test split은
설정 선택에 쓰지 않았습니다.

| 같은 검증 이미지 320장, spike 분류 | FG-ARI ↑ | 전경 IoU ↑ | 물체별 IoU ↑ | 평균 예측 물체 수 |
|---|---:|---:|---:|---:|
| 기존 SW_0001, spectral k=8 | 0.1363 | 0.2720 | 0.1456 | 최대 7 |
| 동료 방식, 전체 spike 상관계수 ≥ 0.95 | 0.0772 | 0.3287 | 0.1736 | 14.88 |
| 동료 방식 변형, 성분별 상관계수 곱 ≥ 0.95 | 0.0702 | 0.3296 | 0.1750 | 18.32 |

**해석:** 연결 성분 방식은 배경과 물체 위치를 더 잘 찾아 전경 IoU와
물체별 IoU가 올랐지만, 한 물체를 여러 조각으로 나눠 예측하는 경향이
강해 FG-ARI가 떨어졌습니다. 이 상태로는 세 점수 동시 개선이 아닙니다.
검증한 임계값 0.50/0.70/0.80/0.90/0.95의 모든 숫자는 `results.json`에
있습니다. 정답 물체 수로 예측 그룹 수를 고르지 않았습니다.

## 정확한 테스트 조건과 코드 변경

- 출처: 동료 브랜치 `patch_v2` 커밋 `5a29422`, `spike_synchrony_components`.
  평균을 뺀 spike 이력의 signed correlation, 임계값 이상인 patch 연결,
  연결 성분별 mask, 가장 큰 성분을 배경으로 처리하는 계산을 독립적으로
  재현했습니다. 추가 변형은 oscillator 성분별 양의 correlation을 곱했습니다.
- 기존 seed-0 40-epoch core checkpoint를 그대로 사용했습니다. 새 학습이나
  core 계산 변경은 없습니다. 256 step 중 앞 64 step을 버리고 spike를 비교했습니다.
- 데이터: CLEVR HDF5 128×128, 이미지 ID 1320–1639의 320장, 정답 mask는
  8×8 pixel의 최빈 object ID로 16×16 patch label을 생성했습니다.
- 구현은 `evaluate.py`에만 추가했습니다. 실제 `patch_v2_sw` classifier에는
  아직 넣지 않았습니다. 공통 `evaluation.py`의 세 지표로 평가했습니다.
- 원본 동료 실험의 이미지 크기·분할과 다르므로, 동료 보고서 점수와 수치를
  직접 비교하지 않았습니다.
